# بررسی سازگاری اولیه دیتابیس

مبنای این یادداشت schema ارسالی در گفتگوست، نه بررسی زنده سرور.

## موجود
- users: حساب کاربران عادی
- admins: حساب مدیران
- useful_files: ماژول فایل‌های مفید موجود؛ بدون بررسی کد نباید برای کتابخانه اسناد جدید استفاده مجدد شود.
- chat_attachments: پیوست‌های چت
- service_requests و ticket_attachments: درخواست خدمات و پیوست‌های مربوط به آن

## نیازهای جدیدی که در schema ارسالی آشکارا دیده نشد
- درخت پوشه‌های شخصی و مشترک
- متادیتای فایل‌های کتابخانه اسناد
- مجوزهای جداگانه کاربران روی پوشه/فایل
- ثبت رویدادهای دسترسی و تغییرات
- نگاشت امن شناسه فایل ذخیره‌سازی به متادیتای پرتال

## طرح پیشنهادی، هنوز اجرا نشود
1. document_folders: نام، والد، نوع personal/shared، مالک کاربر و سازنده
2. document_files: پوشه، نام نمایشی، شناسه ذخیره‌سازی تصادفی، MIME، اندازه، سازنده، زمان‌ها و وضعیت حذف منطقی
3. document_permissions: شناسه پوشه/فایل، شناسه کاربر، can_view/can_download/can_upload/can_edit/can_delete، مدیر اعطاکننده و زمان
4. document_audit_log: کاربر، عملیات، هدف، زمان و نتیجه

## الزامات پیاده‌سازی
- فقط مدیر احراز هویت‌شده مجوز اعطا/لغو کند.
- نبود مجوز یعنی رد دسترسی (deny-by-default).
- کنترل سمت سرور برای نمایش، دانلود، آپلود، ویرایش، حذف و callbackهای ONLYOFFICE لازم است.
- JWT ONLYOFFICE و توکن ذخیره‌سازی هرگز در کد مرورگر یا GitHub قرار نگیرند.
- هر migration ابتدا روی کپی دیتابیس تست شود؛ انتشار به دیتابیس اصلی نیازمند تأیید جداگانه است.
